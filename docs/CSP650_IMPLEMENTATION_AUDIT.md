# CSP650 implementation audit

Date: 4 November 2026. Scope: repository source and documentation only. This is a static, read-only audit of application code; no service, database, model, browser, or test suite was run. “Absent” means no implementation was found in the inspected source, not proof that an external deployment lacks it. Existing runtime configuration, Supabase policies, data, and mail delivery were not inspected.

## Current architecture

The React/Vite client uses Supabase Auth for sign-in and exchanges the access token for a same-origin browser cookie. FastAPI validates the Supabase user and derives `admin` from `app_metadata.role`; its application records and images live in SQLite and local directories. FastAPI calls the loopback Florence-2 service and local Ollama for analysis and report drafting. The demo script runs one FastAPI worker on loopback and exposes it through Cloudflare Tunnel. Evidence: `frontend/src/lib/supabase.ts`, `backend/app/core/auth.py`, `backend/app/repositories/reports.py:69-74`, `backend/app/core/config.py`, `backend/app/api/florence_analysis.py:210-315`, `scripts/run-cloudflare-api.ps1`, `docs/cloudflare-demo-deployment.md`.

The active report path is citizen submission → admin verification/rejection → team assignment (`in_progress`) → admin resolution. Old `processing`/`completed` values remain in client types for legacy records. Evidence: `backend/app/repositories/reports.py:1178-1204,1636-1703,1715-1779`, `frontend/src/types/index.ts:15`, `docs/community-migration.md`.

## Reusable foundations

- Auth and permission boundary: `backend/app/core/auth.py`, `backend/app/api/browser_session.py`, `frontend/src/components/common/RoleGuard.tsx`, `frontend/src/features/authentication/RoleContext.tsx`. Extend trusted role claims server-side; never treat a client route guard as authorization.
- Citizen reporting and AI review: `frontend/src/pages/SubmitReportPage.tsx`, `frontend/src/features/reporting/*`, `backend/app/api/florence_analysis.py`, `backend/app/services/ai/waste_rules.py`, `backend/app/services/ai/confirmed_report_draft.py`. Preserve raw outputs, reviewed corrections, model/rule versions, and uncertainty.
- Map UI and geocoding: `frontend/src/components/location/GoogleMap.tsx`, `LocationPicker.tsx`, `frontend/src/features/location/google-maps.ts`. The marker component can support an incident layer; aggregation and privacy policy still need design.
- Workflow and evidence: `backend/app/repositories/reports.py` status events, assignment, resolution details and local after-photo path; `frontend/src/pages/AdminReportDetailPage.tsx`. The state model needs an explicit assigned stage and staff-scoped transitions.
- Notifications and exports: `backend/app/services/report_email.py` transactional outbox pattern and `frontend/src/pages/AdminDashboardPage.tsx` CSV UI. Both need a Supabase-backed persistence/analytics contract before broadening.
- Demo deployment: `scripts/run-cloudflare-api.ps1`, `scripts/start-cloudflare-demo.ps1`, `docs/cloudflare-demo-deployment.md` keep model services on loopback.

## Security and operational findings

| Priority | Finding, evidence, and action |
| --- | --- |
| High | **Authorization migration:** Staff/Driver does not exist, and current admin permission comes from Supabase `app_metadata` (`backend/app/core/auth.py:96-100,198-208`). Define trusted claims and server-side ownership/team checks before staff endpoints. Review live grants manually as `docs/community-migration.md` requires. |
| High | **Supabase move requires RLS and private assets:** Current local report files require admin auth (`backend/app/api/reports.py:453-480`), while member detail is owner-filtered (`backend/app/api/members.py:52-66`). A new Supabase schema/bucket must enforce equivalent citizen ownership, assigned-staff scope, admin access, private buckets, and short-lived signed reads; public photo URLs would regress privacy. |
| High | **CSV formula injection:** `frontend/src/pages/AdminDashboardPage.tsx:55-70` quotes cells but does not neutralize spreadsheet formulas. A user-controlled location beginning with `=`, `+`, `-`, or `@` could execute when opened in spreadsheet software. Sanitize cells in both future CSV paths and test with malicious values. |
| Medium | **Session roles can outlive a grant change:** `backend/app/api/browser_session.py:26-32` copies the validated identity into a local cookie session; `backend/app/core/auth.py:160-175` reads it without consulting current Supabase metadata on every request. Audit role revocation behavior and invalidate/refresh sessions for role changes before granting staff/admin at scale. |
| Medium | **Cookie request-origin check allows missing Origin:** `backend/app/core/auth.py:164-169` rejects a disallowed Origin on mutating requests but permits an absent Origin. SameSite=Lax and same-origin fetch help, yet a sensitive cookie endpoint should enforce an explicit CSRF strategy and test browser/form edge cases. No exploit was demonstrated. |
| Medium | **CSV and analytics coverage:** Current CSV contains only filtered, browser-loaded summaries (`frontend/src/pages/AdminDashboardPage.tsx:55-70`), with no server-side date range, completeness guarantee, or export audit. Define privileged, paginated export queries and scope before adding PDF. |
| Medium | **Demo availability and data durability:** `scripts/run-cloudflare-api.ps1` runs one local worker; `docs/cloudflare-demo-deployment.md` says the laptop, SQLite, model services, and images must remain available. Back up and reconcile all records/assets before migration; provide a manual fallback when local AI is unavailable. |
| Existing controls | Backend validates Supabase identity/admin role (`backend/app/core/auth.py`), upload type/size/decoded image (`backend/app/services/image_uploads.py`, `backend/app/services/ai/image_validation.py`), loopback Florence URL and production secure cookie (`backend/app/core/config.py`), and HTML email escaping (`backend/app/services/report_email.py`). These are source-level observations, not penetration-test results. |

## Audit limits

No tests were executed. Test files show intended coverage, not passing results. This audit did not access live Supabase project settings, RLS policies, Storage buckets, SMTP inboxes, Cloudflare settings, current SQLite contents, or model output. Two inaccessible local `.pytest_*` cache directories produced file-list warnings; they are generated caches, not application source. The user-supplied CSP650 bullets were treated as the acceptance criteria; no external rubric was assumed.
